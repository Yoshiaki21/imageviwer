# imageviewer

Rust + [GPUI Kit](https://gpui-kit.com)（gpui / gpui-component）製の、Windows 11 と
Manjaro KDE (Linux) 両対応のシンプルな画像ビュワー。

同時に存在するウィンドウは常に 1 つだけで、関連付けから別の画像を開いても新しいウィンドウは
増えず、開いているウィンドウの表示画像だけが切り替わります。

仕様の原典は [`imageviewer_instructions.md`](imageviewer_instructions.md) です。

## ビルドと実行

```bash
cargo build --release          # 実行ファイル: target/release/imageviewer
cargo run -- /path/to/image.png
cargo test
```

`config.toml` と `viewer.log` は**実行ファイルと同じディレクトリ**に作られます。
書き込み可能な場所に実行ファイルを置いてください。

## 操作

### キーボード

| キー | 動作 |
|---|---|
| → | 同じフォルダ内の次の画像（最後の画像なら先頭へ戻る） |
| ← | 同じフォルダ内の前の画像（先頭の画像なら最後へ戻る） |
| ↑ | 前の兄弟フォルダへ移動し、前回そのフォルダで見ていた画像（初めてなら先頭画像）を表示 |
| ↓ | 次の兄弟フォルダへ移動し、前回そのフォルダで見ていた画像（初めてなら先頭画像）を表示 |
| R | 同じフォルダ内のランダムな画像を表示（表示中の画像以外から選ぶ） |
| F5 | 表示中のフォルダのファイル一覧を読み直す（追加したファイルを反映） |
| Delete | 表示中の画像をゴミ箱へ移動し、その次の画像を表示（最後の画像なら先頭へ） |
| Enter | フルスクリーン ⇔ ウィンドウ の切り替え |
| Esc / Ctrl+Q | 終了 |

- 並び順はファイル名の**自然順**（`img2.jpg` → `img10.jpg`）。
- 画像（png/jpg/jpeg）を 1 枚も含まないフォルダは ↑↓ で完全にスキップされます。
  移動先の兄弟フォルダが無いときは「前のフォルダはありません」／「次のフォルダはありません」と表示します。
- R は画像が 1 枚だけのフォルダでは何もしません。
- Delete は完全削除ではなく OS のゴミ箱（Windows のごみ箱／KDE のゴミ箱）へ移します。
  ゴミ箱から戻せるので確認ダイアログは出しません。フォルダが空になったらその旨を表示します。
- 削除済み・壊れている・デコードできない画像は「無いもの」として扱い、次の画像へ進みます。
- フォルダのファイル一覧はフォルダに入ったとき（起動時・関連付けから開いたとき・↑↓）に読み込み、
  同じフォルダ内の移動ではそれを使い回します。ファイル数の多いフォルダでもキーの押しっぱなしで
  表示が追いつくようにするためです。削除・移動されたファイルに当たったときは自動で読み直します。
  見ている間に追加したファイルは、F5 を押すかフォルダに入り直すと表示対象になります。
- フォルダを離れるときに、そのフォルダで見ていた画像のファイル名を `config.toml` の `[folder_history]` に
  記録します（次回起動後も有効）。記録した画像が消えていたり壊れていたりしたら、そのフォルダの先頭から表示します。
  記録するフォルダ数は `max_folders`（既定 100、`0` で記録しない）で、超えたら一番長く見ていないフォルダから忘れます。

Esc と Ctrl+Q は実装指示書にはない追加分です。フルスクリーン中はウィンドウの閉じるボタンが
出ないため、キーボードだけで終了できるようにしています。

### マウス

ウィンドウ全体（画像の上下左右の黒帯も含む）を縦横に 2 等分し、左上から反時計回りに 1〜4 とします。

| | 左 | 右 |
|---|---|---|
| **上** | 1: 前のフォルダ | 4: 次のフォルダ |
| **下** | 2: 前の画像 | 3: 次の画像 |

| 操作 | 動作 |
|---|---|
| 1（左上）をクリック | ↑ と同じ（前の兄弟フォルダ） |
| 2（左下）をクリック | ← と同じ（前の画像） |
| 3（右下）をクリック | → と同じ（次の画像） |
| 4（右上）をクリック | ↓ と同じ（次の兄弟フォルダ） |
| 2・3 を右クリック | R と同じ（ランダムな画像） |
| ダブルクリック（どこでも） | フルスクリーン ⇔ ウィンドウ の切り替え |
| ホイールを下に回す | → と同じ（1 ノッチで 1 枚） |
| ホイールを上に回す | ← と同じ（1 ノッチで 1 枚） |

- シングルクリックはダブルクリックの受付時間（Linux 400ms／Windows は OS の設定値）だけ待ってから
  実行します。ダブルクリックでフルスクリーンにしたときに画像が移動しないようにするためです。
- 右クリックは待たずにすぐ実行します。1・4 の右クリック、中ボタン、3 回目以降の連続クリックは何もしません。
- 高解像度ホイールの細かい入力は積算し、1 ノッチ分に達したら 1 枚進みます。
  横スクロールとタッチパッドのスクロールには反応しません（慣性で何枚も進むのを防ぐため）。

## フォルダ名・ファイル名の表示

画像が切り替わるたび（キー・クリック・ホイール・Delete 後・F5 後・起動時・関連付けから別の画像を開いたとき）に、
ウィンドウ下部中央へ次の 2 行を重ねて表示します。

```
/home/user/Pictures/sample
img10.jpg    5 / 42
```

- 1 行目はフォルダのフルパス（長いときは先頭側を「…」で省略）、2 行目は「ファイル名　何枚目 / 全枚数」。
- 既定で 5 秒表示し、最後の 300ms でフェードアウトします。表示中に切り替えると時間を数え直します。
- 表示時間は `config.toml` の `[overlay] duration_ms` で変更でき、`0` にすると表示しません。
- 表示の上をクリックしても、その下のエリアのクリックとして扱います。

## 起動時の動作

| 状況 | 動作 |
|---|---|
| 引数に画像パスあり | その画像を表示（表示できなければ同じフォルダで最も近い画像） |
| 引数なし・`config.toml` に記録なし | メッセージを表示（Esc / 閉じるで終了） |
| 引数なし・記録のフォルダが無い / 画像が無い | メッセージを表示し、記録を `config.toml` から削除 |
| 引数なし・記録が有効 | 記録されたインデックスの画像を表示（無ければ最も近いもの、同距離なら前方優先） |

起動時は常にウィンドウモードです。フルスクリーン状態は次回に引き継ぎません。
ウィンドウの位置・サイズは前回終了時のものを復元します。

引数にフォルダを渡した場合は、前回そのフォルダで見ていた画像（記録が無ければ先頭画像）を表示します（指示書にはない追加分）。

## 先読み

同じフォルダ内を移動するとき、画像のデコードは別スレッドで行い、画面を止めません。
表示中の画像の前後（既定では進行方向に 4 枚、逆方向に 2 枚）をあらかじめデコードしておくので、
次・前の画像はデコードを待たずに表示されます。複数の画像を並行してデコードします（CPU コア数 − 1、最大 4）。

- 移動先のデコードが終わるまでは前の画像を出したままにし、終わったら画像とファイル名表示を同時に切り替えます。
- キーを押しっぱなしにしてデコードが追いつかないときは、途中の画像を飛ばして最新の移動先を表示します。
- デコード済みの画像は、表示する直前にファイルが消えたり変わったりしていないか確認します。
- 使うメモリは `config.toml` の `[prefetch] memory_mb`（既定 1024MB）までで、超えたら遠い画像から捨てます。
- 起動時・↑↓ の最初の 1 枚と R の移動先は先読みしません。

## 設定ファイル

実行ファイルと同じディレクトリの `config.toml`。終了時に自動で書き出されます。

```toml
[window]
x = 100
y = 100
width = 1024
height = 768

[last_opened]
folder = "/home/user/Pictures/sample"
index = 5

[overlay]
# 画像切り替え時にフォルダ名・ファイル名を表示する時間（ミリ秒）。0 で表示しない。
duration_ms = 5000

[prefetch]
# 表示中の画像の前後を別スレッドで先にデコードしておき、切り替えを速くする。
ahead = 4          # 進行方向に先読みする枚数
behind = 2         # 逆方向（戻る側）にデコード済みで残しておく枚数
memory_mb = 1024   # 先読みに使うメモリの上限（MB）。超えたら遠い画像から捨てる

[logging]
enabled = true          # ログ出力する/しない（未指定時のデフォルト: true）

# 詳細ログ（デバッグ情報）を出力するかどうかの設定。
# デバッグビルドでは常にこの設定に関わらず詳細ログを出力する。
# リリースビルドでは、この項目が未設定または false の場合はエラーのみ出力する。
# 実運用中に不具合の手がかりが欲しい場合のみ、以下のコメントを外して true にしてください。
# verbose = false

[folder_history]
# ↑↓ でフォルダに戻ったとき、前回見ていた画像から表示するために覚えておくフォルダの数。0 で覚えない。
max_folders = 100

# 以下は自動で記録される（最後に見た順）。
[[folder_history.entries]]
folder = "/home/user/Pictures/sample"
file = "img010.jpg"
```

## ログ

実行ファイルと同じディレクトリの `viewer.log` に追記し続けます（ローテーションなし。
肥大化したら手動で削除してください）。

- デバッグビルド: 常に詳細ログ
- リリースビルド: 既定はエラーのみ。`[logging] verbose = true` で詳細ログ

## ファイル関連付け

OS 側の設定手順は [`docs/file-association.md`](docs/file-association.md) を参照してください
（KDE の `.desktop` / MIME 登録、Windows のレジストリ登録）。

## 対応フォーマット

PNG と JPEG のみ。BMP / GIF などは未対応です。拡張子 → フォーマット → デコーダの対応は
`src/media/` にまとまっており、フォーマットを増やすときは `ImageFormat` に列挙子を足すと
コンパイラが対応漏れを指摘します。
